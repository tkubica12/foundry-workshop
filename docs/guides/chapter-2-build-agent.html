Prepared seat

Start in the prepared project.

Synthetic data only. No installation.

Open ai.azure.com with your assigned workshop account. Select the tenant and project from your seat details; check the project name before creating anything.

Confirm with your facilitator that your seat can create agents and personal-information guardrails, select the models below, and read traces. If sign-in or a required control is unavailable, stop and contact your facilitator; do not switch to a personal account or deploy replacements.

Models: admin-connected gpt-5.6-luna and Mistral-Large-3; project-local gpt-5.2. Personal information (PII) includes email addresses. Use only the fictional address supplied here.

Customer conversation

Give the assistant a job.

Leave its tone unconfigured.

  1. Open Build → Agents → New agent → Build an agent. Name it pickup-<your-seat-number> and select Create. If that name exists and is not yours, choose a new suffix.

  2. Under Tools, remove any automatically attached tool, such as Web search, using its ... → Remove menu. Leave knowledge empty. Paste these instructions and select Save if changes are pending.

Instructions

You help customers with fictional click-and-collect orders.
Use only the facts supplied in the conversation.
You cannot look up orders, send messages, or change reservations.

Select gpt-5.6-luna under Admin-connected, save any change.

Why: define what the assistant knows and can do. Do not add a greeting style, empathy rubric, length rule or response template yet.

Check

The configuration shows your instructions and a saved agent version. Leave knowledge and tools empty.

Meet the assistant as a customer.

The message supplies every order fact.

Start New chat. Send:

Customer message

Hi! This is a fictional training case. My order for hand cream was meant to be ready this morning, but I have not received a pickup notice and I am frustrated.
The order is still being prepared. Pickup is allowed only after the ready notification. The store closes at 18:00.
Can you help me work out what to do?

Why: experience a customer-facing answer, not a structured report. All facts come from this message, not a database or document.

Check

You receive an answer about the pickup. Note how it greets you, handles frustration and explains the next step. Flag invented readiness times or claims to have checked the order.

Model comparison

Change the model, not the task.

Two answers give a first impression.

Keep the first answer and its model/version in your notes. Select Mistral-Large-3, save, start New chat, and send the identical customer message.

Why: compare factual restraint, tone and usefulness without changing the instructions or conversation history.

Check

Choose a provisional favourite and name one difference. Both answers may already be good; do not manufacture a failure.

Block, then annotate

Establish an unblocked baseline.

Change only the email between cases.

Switch to gpt-5.2 under Deployments and save. Keep the default guardrail; do not disable existing controls. Send each message in a separate New chat.

Control: no email

Hi! In this fictional training case, my order is still being prepared and pickup requires a ready notification. What should I do?

Same case with synthetic email

Hi! In this fictional training case, my order is still being prepared and pickup requires a ready notification. What should I do?
My contact email is alex.customer@example.com.
Check

Both messages receive an answer without a PII policy block.

Block personal information at input.

Scope the policy to your agent only.

  1. Open Build → Guardrails → Create. Under Sensitive data leakage, set Risk type to PII (Preview), choose Email protection, intervention point User input and action Block. Leave the default controls unchanged.

  2. Select Next to assign the guardrail. Select only your pickup-<your-seat-number> agent; leave all models unselected. Select Next.

  3. Name the policy pickup-pii-<your-seat-number>. Confirm your agent is listed and Models says No models selected, then select Create. Return to your agent and save if changes remain unapplied.

Check

Your agent names the new policy; Email is controlled at User input. If PII, Email, User input or the action is unavailable, stop this section and contact your facilitator. Do not substitute a keyword blocklist.

Why: the platform control, rather than a personality instruction, decides whether this input is accepted.

A block needs a passing control.

Policy attribution matters more than refusal wording.

On gpt-5.2, resend the control and email message, each in a separate New chat.

Check

The control answers. The email message triggers a platform guardrail block identifying personal information at user input. Record the request ID or trace link and policy action.

Annotate detects without blocking.

It does not sanitize the model input.

Open your policy under Build → Guardrails → Edit. Change the Email protection / User input action from Block to Annotate. Keep other controls and the single-agent assignment unchanged, then finish the wizard.

Return to your agent, save any pending changes, start New chat, and resend the exact email message. Keep its response ID or trace link.

Check

The request now completes. The next step must confirm Email was still detected; an answer alone does not prove annotation.

Why: annotation lets you observe a risk without stopping the request. It is not masking or anonymization. Edit only your own policy: changing a policy can affect every agent version assigned to it.

Evidence and next chapter

Find the detection in the trace.

Same email. Different enforcement.

Select Traces beneath the annotated reply. In Trajectories, select its invoke_agent span and open Metadata. Match the response ID and locate microsoft.foundry.content_filter.results.

Check

Under source_type: prompt, find personally_identifiable_information: detected: true, filtered: false, category Email. The blocked call instead records filtered: true.

Why: this connects the visible answer to the platform's decision. Traces can contain the original email, so keep all data synthetic.

Keep the baseline for improvement.

Later, change the prompt and measure again.

Record your agent name/version, original instructions, model, policy name/action and one trace ID in your local notes. Keep the agent on gpt-5.2 with your lab-only Annotate policy.

Knowledge will add facts beyond the message. Custom evaluations will turn impressions of empathy, tone and usefulness into a rubric: baseline run, prompt change, same-case rerun. Keep model, policy and knowledge fixed during that comparison.

Check

Your agent remains available, its original instructions are unchanged, and you can distinguish detected data from blocked data. A neutral prompt may already produce a friendly answer; improvement must be measured, not assumed.

Resume, reset and cleanup

Resume: reopen your assigned tenant, project and pickup-<seat> agent. Check its saved version, gpt-5.2 model and your named guardrail policy before continuing at the last completed checkpoint. Do not create a duplicate agent to recover a missing trace; wait about two minutes, then ask your facilitator with the response ID.

Reset this exercise: first save your notes and version IDs. In your own agent, restore the three-line baseline instructions, select gpt-5.2 and save a new version. In your own lab-only policy, restore Email protection / User input / Block before replaying the Block and Annotate steps. Keep other controls unchanged. Ask your facilitator instead of editing a shared policy.

Cleanup: keep your agent and its lab-only policy for Lab 3. After your final lab, export your notes and give the facilitator your seat, agent and policy names. The facilitator owns removal of workshop resources; do not delete a project, model deployment or shared policy. Keep using synthetic data while Annotate is enabled; do not leave that lab setting attached to a production agent.
