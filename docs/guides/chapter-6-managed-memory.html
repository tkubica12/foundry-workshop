Chapter 6 · Hands-on

Remember across conversations

Try an agent without memory. Enable managed memory, inspect a stored preference and recover a previous discussion in a new chat.

  • Time20 minutes core; 5 minutes recovery and discussion
  • EnvironmentFoundry (new), assigned account, Memory preview
  • OutcomeA user profile and a chat summary verified across new chats

Prepare / 3 minutes

Sign in to ai.azure.com with your assigned workshop account and New Foundry enabled. Confirm your assigned tenant, subscription and project. Keep the same signed-in identity throughout this lab.

The facilitator prepares a compatible chat deployment, an embedding deployment and permission to create agents and memory stores. Memory uses additional model calls and is a preview; do not deploy models or change permissions during the lab.

  1. Open Build → Agents → New agent → Build an agent. In Czech, use Agenti → Nový agent → Sestavit agenta. Name your text agent memory-<seat>-<run>, replacing both placeholders with your assigned seat and a fresh run label. Select Create agent and open playground.

  2. Select the facilitator-confirmed chat deployment in Model. Remove any default web-search tool using its … → Remove menu. Leave Knowledge and Memory unattached. Keep agents from earlier labs unchanged.

  3. Paste these instructions and select Save. Keep the instructions and model fixed in both halves of the comparison.

Agent instructions

Answer briefly in the language of the user. Use the current conversation and available memory tools for personal facts and previous discussions. If evidence is missing, say you do not know. Do not invent preferences or past conversations.
Check

Your own new text agent opens in Playground, has no tools, knowledge or memory attached, and uses the prepared deployment. If Memory or the deployments are missing, stop for facilitator help.

Try without memory / 3 minutes

  1. In Playground, send this fictional preference and discussion. Wait for a completed reply.

Preference and discussion

Remember that I like apples. Today we discussed a fruit snack for a fictional hiking trip: pack apples in a reusable box.

  1. Select New chat (Nový chat), the chat-bubble-plus control above the chat pane. Confirm the previous messages disappear. Send:

Recall without memory

What fruit do I like? Have we ever discussed fruit?
Check

The agent cannot substantiate your preference or the previous discussion. Record the answer. A claim such as “I’ll remember” in the first chat is not evidence of storage. If it guesses apples, treat that as a failed baseline, not memory.

Without an attached memory store, this agent does not create a managed user profile or chat summary. It can still use earlier messages inside the same chat; that is conversation context, not cross-session memory.

Enable managed memory / 4 minutes

  1. Open Build → Memory → Create memory store (Paměť → Vytvořit paměťové úložiště). Use a fresh name memory-store-<seat>-<run>. Select the prepared Chat completion model and Embedding model deployments; do not accept unverified defaults.

  2. Expand Advanced settings (Rozšířená nastavení). Enable User profile and Chat summary extraction (Povolit profil uživatele, Povolit souhrn chatu). Disable Procedural memory; it is outside this lab. Leave profile details and TTL at the facilitator-approved defaults. Select Create.

  3. Return to Build → Agents, open your agent's Playground, expand Memory, and select Add. Choose your new store from Recent, or Browse all memory stores. Do not choose another person's store or automatic creation.

  4. Select the gear beside the attached store, Configure memory store (Konfigurovat úložiště paměti). Keep Scope (Obor) as {{$userId}} and Update delay (seconds) as 30. Save the dialog, then Save the agent.

  5. Select New chat. Send the exact preference and discussion prompt again and wait for the completed reply. Enabling memory does not prove old, memory-disabled chats were imported.

Check

Your store is attached to the saved agent version. The seed prompt has been sent after attachment. Wait at least 30 seconds of inactivity, then inspect storage; extraction can take longer than the configured delay.

{{$userId}} resolves to the authenticated user's identity. Keep it stable while changing chats. A shared static scope would mix users; a new scope for every chat would prevent recall.

Inspect and recall / 8 minutes

  1. Open Build → Memory, select your store's name, then the Memories tab (Paměti). Keep Scope as {{$userId}}. Clear any search text and choose Kind → User profile (Druh → Profil uživatele).

  2. Find a row with kind user_profile and content meaning “The user likes apples.” Wording can differ. Do not use Create memory to insert the answer manually.

  3. Return to your agent's Playground. Select New chat, confirm the empty chat, and send:

Recall the profile

What fruit do I like?
Check

You have both a stored user_profile row and a fresh-chat answer identifying apples. Do not include “apples” in the recall question or agent instructions.

  1. Open your store's Memories tab again. Keep the same scope and choose Kind → Chat summary (Druh → Souhrn chatu). Find a chat_summary row describing the fictional hiking snack and its reusable box.

  2. Read the summary. It is a distilled record, not necessarily a verbatim transcript or one row per chat. Return to Playground and select New chat again. Send:

Recall a previous discussion

Have we ever discussed fruit? What did we plan for the fictional hiking snack, and how were we going to pack it?
Check

The new answer recalls apples and the reusable box, matching the stored summary. A “yes” or the apple preference alone cannot distinguish discussion recall from profile recall. Expand the answer's Trace if available and inspect its memory-search result for supporting context.

Connect this to Lab 5: a knowledge base supplies curated facts; memory supplies context learned from interactions. Neither is a substitute for access control, and retrieved memory can be incomplete or wrong.

Recovery and cleanup / 2 minutes

  • No stored row: confirm the saved agent version, attached store, enabled extraction type and identical identity/scope. Wait, refresh the Memories tab every 30 seconds, and stop after three minutes for facilitator help. Do not manufacture a row.
  • A row exists but recall fails: check the current agent version and scope; inspect Trace for a memory-search call and retrieved content. Retry once in a new chat without adding the answer to the question.
  • Model error, including unsupported reasoning.effort: the selected deployment is not qualified for this playground configuration. Ask the facilitator for the compatible prepared deployment and repeat the baseline and candidate with that same model.
  • Missing menu or access denied: confirm New Foundry and the assigned project. Stop for facilitator help; do not use keys, another account or a broader role to bypass the problem.

Resume: reopen your named agent and store with the same account and scope. Continue from the last stored-row checkpoint. Reset: use fresh run-labelled agent and store names and restart the comparison; changing chats alone preserves long-term memory.

Cleanup: only when both resources belong exclusively to this run, open your agent's top … → Delete agent menu (Odstranit agenta). Type its exact name into the confirmation and select Delete. Then open your store under Build → Memory, select its top … → Delete memory store (Odstranit paměťové úložiště), check the displayed name, and confirm deletion. Refresh both lists and verify both names are absent. If deletion fails, report the retained name to the facilitator. Never delete a shared store, model, project or resource group.

Deleting or detaching an agent is not proof its memory store was deleted. Store deletion is not a claim that traces, chat records or platform logs were erased. Use only the fictional inputs in this lab.

Optional extension: after the core, correct the fictional fruit preference and inspect how the profile changes. Verify the stored row and a fresh-chat answer; an acknowledgment alone is not enough.

Menu paths were checked in the native Foundry portal on 1 October 2026, including the Czech labels shown above. Preview labels and availability can change; follow the current controls, not a missing legacy menu.

Read Create and use memory for identity resolution, update delay, direct remember/forget and retention; read Memory concepts for the extraction and retrieval model. A prompt asking to remember can trigger a direct memory command; summary extraction still needs processing time. Per-user scope partitions records but does not replace project authorization or trusted identity handling in a production application.

A profile remembers a preference. A summary remembers a discussion. Verify both in storage and in a genuinely new chat.
