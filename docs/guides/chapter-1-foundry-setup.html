Account and access

Have your assigned account, tenant, shared subscription, existing resource group and seat number ready. Get these details from your facilitator; do not use a personal subscription or invent a resource group.

  1. Open ai.azure.com. Sign in with the assigned Microsoft Entra account and complete MFA if prompted. Use the New Foundry experience if the portal offers that toggle.

  2. Check the signed-in account and directory against your seat details. If you need to verify Azure access, open portal.azure.com with the same identity. In Subscriptions, check the assigned subscription; in Resource groups, find your assigned group. Azure portal sign-in is a reference check, not a separate deployment step.

  3. Confirm with your facilitator that this account can create a Foundry resource and project in your group, deploy models, and run playground inference. The facilitator must have enabled Fireworks.EnableDeploy for the subscription and approved any required provider terms before the lab. Do not register subscription-wide features or change role assignments yourself.

No CLI, SDK, API key or local installation is needed. Use synthetic prompts only.

Check

You are signed in to Foundry with the expected identity, and you know exactly which subscription and resource group to select. Stop here if access is missing.

Your project

  1. Open the project selector in the upper-left corner and select Create new project. On a first visit, use the home page's project creation action.

  2. Enter workshop-<seat-number> as the project name. For example, seat 007 uses workshop-007. Replace the example number with your own; never type the angle brackets.

  3. Open Advanced options. Select your assigned Subscription, choose your existing Resource group, and set Location to Sweden Central (swedencentral). The portal also creates a parent Foundry resource. If it asks for that resource's name, use foundry-workshop-<seat-number>-<unique-suffix>, for example foundry-workshop-007-a1b2; keep the generated name if it is valid and belongs to your group.

  4. Review the fields, then select Create or Create project, as shown in the dialog. Wait for creation to finish and check the project name in the selector. If creation is still pending after five minutes, ask the facilitator instead of submitting it again.

Why: the resource group scopes your Azure resources; the Foundry resource hosts deployments; the project organizes your work. A deployment is an instance of a model, not a new project.

Check

Your project opens. Its parent resource is in your assigned subscription and resource group, with location Sweden Central. Record the project and parent-resource names for resume and cleanup.

Model deployments

Use Global Standard and 100,000 tokens per minute for exactly one primary deployment. Try gpt-6.1-sol first; if there is insufficient quota or it is unavailable, try gpt-6-sol, then gpt-5.6-sol. Do not deploy all three.

  1. In your project, open Build → Models. This lists deployments in the parent resource. To browse models, use the model-catalog action on this page if offered; otherwise select Discover → Models.

  2. Search for gpt-6.1-sol and open its model card. Select Deploy → Custom settings, not Default settings. Check the target resource and project before continuing.

  3. Use deployment name primary-<seat-number>. Set Deployment type to Global Standard. Set Tokens per Minute Rate Limit to 100000. If the control uses thousands of TPM, enter 100 and verify that the summary means 100,000 TPM. Keep the default guardrail and other settings unchanged.

  4. Select Deploy. Return to Build → Models and verify Succeeded. If the dialog reports insufficient quota, close it and repeat the custom deployment with the next primary model, keeping the same type and TPM. Before retrying after a submitted deployment, inspect its status: do not create a duplicate while it is pending or reuse its name while a failed deployment still exists.

Why custom settings: assigned TPM consumes the subscription's available quota. A small allocation leaves room for other seats. TPM is a rate limit, not a spending cap or a guarantee of throughput. Global Standard can process prompts outside Sweden; the project's region does not impose regional inference residency.

Check

Exactly one primary model is deployed successfully, with Global Standard and 100,000 TPM. Record its actual model ID, deployment name and version. If none of the three fits, stop and ask the facilitator; do not increase capacity, change region or edit another seat's deployment.

Core check

Your primary is successful at 100,000 TPM, Luna is successful at 50,000 TPM, and GLM Flash has been submitted at 50,000 TPM with its status recorded. If GLM is pending, defer its success check rather than counting it as complete. These are separate allocations, not one interchangeable quota pool. If either additional model or its required settings are unavailable, ask the facilitator; no substitute is specified for these two models.

First replies

  1. In Build → Models, select your primary deployment to open its Playground. Check the selected deployment name before sending a message.

  2. Start New chat if a previous conversation is open. Copy and send the prompt below. Wait for a nonempty reply; its exact wording will vary.

  3. Repeat in a fresh chat for your luna-<seat-number> deployment. Then test glm-flash-<seat-number> only if its status is Succeeded. If GLM is pending, mark its hello check Not yet tested, continue to the next lab after facilitator confirmation, and return to this step once deployment succeeds. Confirm the deployment selector each time. Leave tools and files unused.

Core check

The primary model and Luna each return a nonempty answer without an error. Record GLM's reply if ready, or its pending status and deferred hello check.

Final check, after pending work: each of your three deployments has status Succeeded and returns a nonempty answer without an error. Note any pending or failed checks separately; do not count a deployment status alone as a successful conversation.

Connect it: identify the subscription and resource group, the parent Foundry resource, the project, the model ID and the deployment name. The playground sends inference requests to the selected deployment. Later, applications use that deployment name to select the same instance.

Next: keep this project and its models. In Lab 2, reuse your primary Sol deployment and compare it with Luna or GLM Flash once ready. You may use another previously deployed model if capacity differs and the facilitator confirms it supports the required agent features. Confirm guardrails and trace access separately; connect Application Insights in your own project before sending agent messages. A successful playground reply does not prove those capabilities.

Troubleshooting

Symptoms and safe recovery
SymptomAction
Wrong directory, missing subscription or resource groupCheck the account and assigned directory. Ask the facilitator to verify your seat details. Do not create a new group or use another subscription.
403, permission error or Azure Policy rejectionStop and share the failed operation and request/correlation ID if available. The facilitator resolves access or policy; do not assign yourself broader roles.
Primary model lacks 100,000 TPMUse the documented fallback order. If all three are blocked, stop. Never free capacity by changing someone else's deployment.
Fireworks unavailable, terms blocked, or Global Standard / 50,000 TPM not offeredAsk the facilitator to check subscription enablement, provider eligibility, region and quota. Do not switch to provisioned capacity or another region.
Deployment pending or creation times outReopen Build → Models and inspect the existing deployment before any retry. Refresh at most twice, one minute apart; record pending work for the facilitator. Fireworks can take up to 30 minutes.
Playground shows 429 or a transient errorWait 30 seconds and retry once, then wait 60 seconds and retry once. If it still fails, stop and share the deployment name, status and request ID. Do not raise TPM.
Playground has no reply after two minutesCheck the selected deployment and its status. Ask the facilitator before resubmitting; do not repeatedly send the same request.

Share only the operation, resource/deployment name, error code and correlation ID needed for diagnosis. Do not share passwords, access tokens or keys.

Resume, reset and cleanup

Resume: sign in to the same tenant, reopen your recorded project and check the existing deployments' model IDs, types, TPM and status. Continue at the first incomplete checkpoint. Never create a second project just because a page reload lost your place.

Reset: use New chat in each playground. If a resource or deployment must be repaired, ask the facilitator to inspect your recorded names first; do not delete and redeploy to recover from an unknown status.

Cleanup: keep the project and all three deployments for the workshop. After the final lab, give the facilitator your seat number, resource group, parent-resource name, project name and deployment names, including anything still pending or failed. The facilitator owns deletion. Do not delete the shared subscription, resource group or anyone else's resources.

Explain why you selected custom settings, why a fallback changes the model rather than capacity, and why Sweden Central does not constrain Global Standard inference to Sweden. Do not add deployments or increase quota for this extension.
